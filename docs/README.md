# TSZ Documentation

This directory is the durable documentation surface for `tsz`. The roadmap in
`docs/plan/ROADMAP.md` remains the planning source of truth; the pages below
explain architecture, behavior, setup, and generated reference material.

## Start Here

- [`docs/how-tsz-works/README.md`](how-tsz-works/README.md) is the broad codebase
  guide. It explains how the compiler works end to end and links to a generated
  inventory that mentions every repository file.
- [`docs/architecture/BOUNDARIES.md`](architecture/BOUNDARIES.md) defines the
  layer ownership rules: scanner, parser, binder, checker, solver, emitter,
  project, LSP, and diagnostics.
- [`docs/plan/ROADMAP.md`](plan/ROADMAP.md) defines the four current goals:
  `green`, `fast`, `grow`, and `hold`.

## Architecture And Specs

- [`docs/architecture/`](architecture/) contains durable architecture contracts,
  boundary inventories, emit architecture, cache ownership, and parallel
  checking notes.
- [`docs/specs/`](specs/) contains behavior-facing specs for diagnostics, TS
  directives, TypeScript lib loading, `try-tsz`, and unsoundness cataloging.
- [`docs/development/TOOLING.md`](development/TOOLING.md) and
  [`docs/DEVELOPMENT.md`](DEVELOPMENT.md) cover local development and tooling.

## Product And Site Docs

- [`docs/site/`](site/) feeds the website-facing documentation for installation,
  benchmark pages, compatibility, and Sound Mode.
- [`docs/superpowers/`](superpowers/) stores focused design/spec documents for
  larger workflow experiments.

## Generated Reference

- [`docs/how-tsz-works/file-inventory/`](how-tsz-works/file-inventory/) is
  generated by `scripts/docs/generate-how-tsz-inventory.mjs`.
- Coverage is checked by `scripts/docs/check-how-tsz-docs-coverage.mjs`.
